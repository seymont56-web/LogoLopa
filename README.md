# LogoLopa

**LogoLopa** — веб-сервис с развивающими логопедическими играми для учеников и панелью управления для учителя. Учитель создаёт учеников, управляет доступом к играм и просматривает результаты прохождения, а ученик после входа видит только разрешённые ему игры.

## Возможности

- авторизация пользователей по ролям: `teacher` и `student`;
- отдельная панель учителя;
- создание учеников с временным паролем;
- редактирование имени ученика;
- сброс пароля ученика;
- открытие и закрытие доступа к отдельным играм;
- быстрое открытие или закрытие всех игр для ученика;
- личный кабинет ученика со списком доступных игр;
- запуск игр внутри модального окна через `iframe`;
- сохранение результатов прохождения игр;
- просмотр истории результатов ученика по каждой игре;
- смена временного пароля учеником в профиле;
- защита форм с помощью CSRF-токена;
- хранение паролей в виде хеша.

## База данных

В проекте используется база данных `logop_games`. Основные таблицы:

| Таблица | Назначение |
|---|---|
| `users` | Пользователи сервиса: учитель и ученики. |
| `games` | Список игр, их коды, названия и пути к HTML-файлам. |
| `student_game_access` | Связь учеников с играми и признак доступности игры. |
| `game_result` | История прохождения игр учениками: правильные ответы, неправильные ответы, время прохождения и дата завершения. |

### Таблица `users`

Хранит данные пользователей:

- `id` — идентификатор пользователя;
- `role` — роль пользователя: `teacher` или `student`;
- `login` — логин;
- `pass_hash` — хеш пароля;
- `display_name` — отображаемое имя;
- `created_at` — дата создания;
- `must_change_pass` — признак необходимости сменить временный пароль.

### Таблица `games`

Хранит список игр:

- `id` — идентификатор игры;
- `code` — код игры, например `game1`;
- `title` — название игры;
- `path` — путь к HTML-файлу игры.

В стандартном дампе добавлены 5 игр:

1. `Лопа и пропавшие гласные`
2. `Лопа и загадочные карточки`
3. `Поймай гласный звук`
4. `Волшебные жетоны`
5. `Лопа сортирует звуки`

### Таблица `student_game_access`

Хранит настройки доступа учеников к играм:

- `student_id` — идентификатор ученика;
- `game_id` — идентификатор игры;
- `is_enabled` — доступность игры: `1` — открыта, `0` — закрыта.

Для таблицы настроены внешние ключи на `users.id` и `games.id`. При удалении ученика или игры связанные записи доступа удаляются автоматически.

### Таблица `game_result`

Хранит результаты прохождения игр:

- `id` — идентификатор результата;
- `student_id` — идентификатор ученика;
- `game_id` — идентификатор игры;
- `correct_answers` — количество правильных ответов;
- `incorrect_answers` — количество неправильных ответов;
- `time_spent` — время прохождения в секундах;
- `completed_at` — дата и время завершения игры.

Для таблицы настроены внешние ключи на `users.id` и `games.id`. При удалении ученика или игры связанные результаты удаляются автоматически.

## Установка и запуск

### 1. Склонируйте репозиторий

```bash
git clone https://github.com/seymont56-web/LogoLopa.git
```

### 2. Переместите проект на локальный сервер

Поместите папку проекта в директорию веб-сервера, например:

```text
htdocs/Веб-сервис
```

Для XAMPP это может быть:

```text
C:/xampp/htdocs/Веб-сервис
```

### 3. Создайте базу данных

Откройте phpMyAdmin и создайте базу данных:

```sql
CREATE DATABASE logop_games CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

Затем импортируйте файл:

```text
logop_games.sql
```

### 4. Настройте подключение к базе данных

Откройте файл:

```text
inc/config.php
```

Проверьте параметры подключения:

```php
const DB_HOST = '127.0.0.1';
const DB_PORT = 3307;
const DB_NAME = 'logop_games';
const DB_USER = 'root';
const DB_PASS = '';
```

Если MySQL работает на стандартном порту, замените порт на `3306`:

```php
const DB_PORT = 3306;
```

### 5. Откройте сервис

Перейдите по адресу:

```text
http://localhost/Веб-сервис/
```

Если проект находится во вложенной папке, укажите путь к этой папке.

## Роли пользователей

### Учитель

Учитель может:

- входить в панель управления;
- создавать новых учеников;
- задавать ученику логин и временный пароль;
- редактировать имя ученика;
- сбрасывать пароль ученика;
- открывать или закрывать доступ к отдельным играм;
- открывать или закрывать все игры сразу;
- просматривать результаты прохождения игр;
- удалять ученика.

### Ученик

Ученик может:

- входить в личный кабинет;
- видеть список доступных ему игр;
- запускать игры в окне на странице;
- проходить игры;
- отправлять результаты прохождения;
- менять пароль в профиле.

## Сохранение результатов игр

Результаты отправляются в файл:

```text
save_result.php
```

Сервис сохраняет результат только для авторизованного ученика и только по игре, которая открыта этому ученику в таблице `student_game_access`.

Пример сохраняемых данных:

```json
{
  "game_id": 1,
  "correct_answers": 6,
  "incorrect_answers": 1,
  "time_spent": 27
}
```

После успешной проверки данные записываются в таблицу `game_result`.

## Как добавить новую игру

1. Создайте папку новой игры в директории `games`, например:

```text
games/game6/
```

2. Добавьте в неё файл `index.html` и необходимые файлы игры.

3. Добавьте запись в таблицу `games`:

```sql
INSERT INTO games (code, title, path)
VALUES ('game6', 'Название новой игры', '/Веб-сервис/games/game6/index.html');
```

4. Для существующих учеников настройте доступ к новой игре в панели учителя.

## Безопасность

В проекте используются базовые меры защиты:

- пароли сохраняются через `password_hash`;
- вход проверяется через `password_verify`;
- формы защищены CSRF-токеном;
- вывод пользовательских данных экранируется через `htmlspecialchars`;
- доступ к страницам ограничивается по роли пользователя;
- результат игры сохраняется только после проверки доступа ученика к игре.

## Возможные проблемы

### Ошибка подключения к базе данных

Проверьте значения в `inc/config.php`: хост, порт, имя базы, пользователя и пароль.

### После входа появляется ошибка 403

Пользователь пытается открыть страницу, которая не соответствует его роли. Например, ученик не может открыть панель учителя.

### Игра не открывается

Проверьте путь к игре в таблице `games`. Он должен вести к существующему файлу `index.html`.

### Результат игры не сохраняется

Проверьте, что:

- таблица `game_result` импортирована из актуального дампа;
- ученик авторизован;
- игра существует в таблице `games`;
- ученику открыт доступ к этой игре в `student_game_access`;
- игра отправляет `game_id`, `correct_answers`, `incorrect_answers` и `time_spent`.
